Co-management: SCCM → Intune

Phased cloud attach so workloads move without a risky big-bang—clear ownership between config manager and Intune.

Hybrid infrastructure

Same estate, clearer handover

Co-management lets you attach Intune to existing SCCM-managed devices so you can shift workloads—compliance, apps, Windows Update—with testing and rollback.

I focus on making the split intentional: which workloads stay on CM first, which move to Intune next, and how compliance and reporting stay trustworthy during the transition. That usually means enrollment alignment, collection and AAD group mapping, and cutover plans that operations can actually run without surprise gaps in patch or app coverage.

Objectives

  • Enable cloud attach without destabilising existing CM processes.
  • Improve update and compliance coverage with a single joined device story.
  • Reduce long-term operational overhead as Intune takes suitable workloads.

Responsibilities

  • Planned co-management prerequisites, PKI/HTTPS, and client settings for a clean attach.
  • Staged workload shifts (e.g. compliance, resource access policies) with validation gates.
  • Aligned CM collections and Entra groups so targeting stays understandable for admins.

Technologies & tools

  • Microsoft Intune
  • Configuration Manager
  • Entra ID / Hybrid join
  • Cloud Management Gateway

Impact & outcomes

  • Safer path to Intune than lift-and-shift re-enrollment for large estates.
  • Better visibility and consistency once key workloads landed in the right tool.
  • Less duplicate effort between CM and cloud for the same device.
